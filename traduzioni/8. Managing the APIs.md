# Che cos'è Amazon API Gateway?
Allora, che cos'è Amazon API Gateway? Beh, diamo un'occhiata più da vicino. Quando parliamo di API Gateway, parliamo di ospitare le tue API in AWS. Quindi, in generale, esporrai i tuoi servizi di backend.

Quindi abbiamo un'interfaccia, un modo per comunicare, e sappiamo come comunicare tra client e back-end. Il modo in cui puoi creare, ospitare, mantenere, monitorare e mettere in sicurezza le tue API in AWS è usare Amazon API Gateway. E API Gateway si integra con i servizi AWS.

Quello di cui parleremo probabilmente di più in questo corso è come API Gateway funzioni molto bene con Lambda. Quindi puoi prendere una funzione Lambda e metterle davanti API Gateway, e poi, per invocare la funzione Lambda, passi attraverso API Gateway. Puoi anche integrare API Gateway direttamente con altri servizi AWS, come una tabella DynamoDB, di cui ti mostrerò un esempio, o altri servizi AWS.

Quindi, quando interagisci con questi servizi, come DynamoDB ad esempio, se vuoi inserire un item in quella tabella, chiami l'API PutItem. Quell'API si aspetta una certa struttura per l'input e puoi fare in modo che API Gateway riceva una request, costruisca quell'input e poi lo passi al servizio AWS di back-end. Quindi questo è supportato, e puoi anche mettere API Gateway davanti alle tue API ospitate su istanze EC2, così come a servizi di terze parti. Quindi questo può funzionare anche con qualsiasi cosa abbia un endpoint HTTP, ad esempio. API Gateway supporta un paio di tipi diversi di API.

Puoi anche controllare e gestire l'accesso. Con la trasformazione dei dati, stiamo dicendo che la request in arrivo deve essere modificata prima di raggiungere il nostro back-end. Questo può servire per i test. Può servire per il mocking. Ne parleremo meglio tra poco, ma i mock sono supportati. E infine, API Gateway supporta il response caching. Il response caching è una funzionalità di API Gateway per cui, quando la abiliti, puoi stabilire per quanto tempo vuoi mantenere i dati in una cache, e questo può aiutarti a scaricare le request dal tuo back-end.

Se hai molti client che richiedono gli stessi dati più e più volte, puoi mettere in cache quei dati nella response cache. E poi, se un utente recupera o richiede quei dati, questi vengono caricati nella cache, e gli utenti successivi, entro il suo time to live, potranno semplicemente usarli dalla cache. Questo può aiutarti a ridurre la latenza per i tuoi utenti finali, e può anche aiutarti a scaricare quelle request dal tuo back-end, il che a sua volta, in alcuni casi, può aiutarti a ottimizzare i costi.

# API Design as Code
Avrai sentito parlare di infrastructure as code, ma io voglio parlarti di API design as code. Al giorno d'oggi ci piace fare tutto come codice. Quindi, una volta che hai la tua API, averla di per sé è ottimo, ma come ti integrerai con altri client? Come faranno le persone a sapere com'è fatta la tua API?

In API Gateway aderiamo agli standard OpenAPI, e Swagger è uno di quegli strumenti che usano anch'essi lo standard OpenAPI. Quello che questo ti permette di fare è descrivere o definire la tua API usando un file YAML che segue un formato leggibile sia dalle persone che dalle macchine. Quindi serve a un paio di scopi diversi.

Invece di progettare la tua API nella console, puntando e cliccando, puoi scegliere di progettarla usando qualcosa come YAML secondo la specifica OpenAPI, magari con uno strumento come Swagger.

Qui puoi configurare i tuoi path, le tue resource, i tuoi method, e puoi anche definire in questo documento quali tipi di integrazione avrai. Quindi puoi prendere questo documento e importare quell'API in determinati strumenti per ospitarla. Questo può essere davvero utile nella fase di design. La progetto tutta qui sulla carta e poi la importo. Oppure puoi fare il contrario e dire: "Ho progettato tutto nella console e ora voglio esportarlo come file Swagger da condividere con altri".

Questo funge in un certo senso da documentazione, perché qualcuno può leggerlo e capire meglio cosa fa la tua API e come interagire con essa. Può aiutarti a velocizzare lo sviluppo, perché puoi effettivamente usare questi file, e ci sono strumenti che prendono in input file OpenAPI e possono generare codice per te. Quindi possono generare i client per interagire con quelle API. È quindi un ottimo modo per documentare la tua API e velocizzare lo sviluppo.

E poi, siamo sviluppatori, giusto? Quindi quello che ti consigliamo è di salvare questi file in un repository da qualche parte. In questo modo, se devi fare una modifica alla tua API, proprio come con l'infrastructure as code, invece di entrare e fare la modifica manualmente, posso modificare un file di configurazione e poi importarlo nella nostra API per creare la versione successiva, cose del genere.

Quindi questo è OpenAPI, Swagger è uno degli strumenti che aderiscono a OpenAPI, e API Gateway funziona con questo standard.
